# AI 工作台：让智能体与项目共同成长

一套面向个人和小团队的文件式工作方法：把项目、知识、规则和验证证据放在容易查找的位置，让 AI 在不同会话中延续工作，并只读取当前任务需要的经验。

[快速开始](docs/quickstart.md) · [已有框架优化](docs/upgrade.md) · [不同智能体使用](docs/platforms.md) · [给任意智能体的启动指令](docs/agent-prompt.md) · [方法与目录](docs/method.md) · [虚构示例](docs/example.md) · [隐私与公开检查](docs/privacy.md) · [兼容性](docs/compatibility.md)

## 能解决什么

- 多个项目长期并行：先判断是继续旧工作线，还是创建独立项目。
- 上下文过多：共通规则保持精简，专项经验先查索引再按任务选读。
- 知识散在聊天中：原始资料留在项目，值得复用的结论进入知识区，并保留来源和状态。
- 交付状态含糊：区分已生成、已检查、真实使用和用户认可；检查结果绑定版本。
- 换一个智能体：使用同一套普通文件与通用启动指令；具体权限及自动加载能力以工具实际情况为准。

## 两种使用方式

已有知识库或工作台：先备份、检查现有结构，并按 [已有框架优化](docs/upgrade.md) 选择性改造，提供[可复制提示词](docs/upgrade-prompt.md)。不需要 Obsidian。

还没有工作台：按照下面的步骤，从空白模板开始。

## 立即体验

1. 下载仓库，在本机新建一个**空文件夹**作为自己的工作台。
2. 将 `starter/` 下的全部内容（包括隐藏文件）复制到空文件夹，保留目录结构。不要覆盖已有工作台。
3. 在支持本地文件操作的智能体中打开该文件夹。将 [启动指令](docs/agent-prompt.md) 发给智能体，告诉它你的第一个目标。
4. 先做一个小任务，检查文件位置与交付，再逐步按自己的需求修改规则。

详细操作、已有目录接入和受限智能体的替代方法见[快速开始](docs/quickstart.md) · [已有框架优化](docs/upgrade.md) · [不同智能体使用](docs/platforms.md)。智能体能否实际读写本地文件、联网或运行工具，取决于它的产品和授权；提示词不会自行授予权限。

## 方法来源

本项目的知识分层受 [Andrej Karpathy 的 LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 启发：原始资料、可维护的 Wiki、规则，以及资料摄入、查询和检查。这里进一步结合持续项目、验收、按任务选读和隐私边界，提供一套可调整的实例。原文是构想说明，并不意味着其作者认可本项目。
