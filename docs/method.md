# 工作方法

## 五类信息，各有入口

| 内容 | 放在哪里 | 目的 |
|---|---|---|
| 工作规则 | 根目录 AGENTS.md | 提供短小的启动路由和权限边界 |
| 项目进行状态 | 对应项目 README | 记录目标、当前阶段、交付和证据 |
| 原件、过程、交付 | 项目的 inputs、work、outputs | 保留来源并区分过程和成果 |
| 可复用知识 | knowledge/ | 有来源、状态和适用范围的综合 |
| 历史事件和验证 | 项目的 logs | 记录测试、问题及当前版本的证据 |

文档中的结论不能自动代替原始证据；对外事实、时效信息和高影响判断需要对应来源与复核。目录是起点，可按实际工作调整；更改后同步入口。

## 一次工作怎样流转

1. **判断归属**：先查项目索引和相近项目 README，依据目标、素材、交付和维护关系，决定续作或新项目。
2. **缩小阅读范围**：读根规则和当前项目状态，再从经验索引选择相关条目；混合任务取并集，出现具体问题再回溯来源。
3. **准备并执行**：确认目标与边界；原始资料保留，过程和结果分别归位；能力或授权不明确时先核实。
4. **验证并记录**：按本次交付实际检查，记录版本、证据和未覆盖范围；旧版本通过不自动转给新版本。
5. **选择性沉淀**：值得跨项目复用的经验，先查是否有相关知识卡；更新或创建卡片，留下来源和适用范围，并更新知识索引与日志。

知识区的摄入、查询、检查细则见 `starter/knowledge/README.md`。无需为每次一次性问答制造文档，也无需为了整理而改写或搬迁原件。

## 信息随时间变化

项目 README 负责当前状态；知识卡负责有边界的综合；日志保留发生过的事。来源是否可得、过去是否检查过、本机工具现在能否运行，分别描述。信息冲突时保留来源与日期；高影响结论由用户决定。
