# 已有知识库：安全地借用方法

如果你已经根据 LLM Wiki 或其他方法建立了知识库，可以继续使用原有目录、索引、日志和规则。本指南帮助你有选择地加入项目接续、任务选读、验收和经验沉淀；不要求使用 Obsidian，也不要求改名或搬迁现有文件。

## 先做一份能恢复的备份

将现有资料备份到独立位置，并确认能打开和恢复。若使用云盘、数据库或应用内知识库，先了解导出是否完整。不要把本包的 starter 直接覆盖到已有目录；特别留意 AGENTS.md、CLAUDE.md、索引、日志及已有自动化的同名冲突。

## 选择一种使用方式

- **先诊断**：发送 [已有框架改造提示词](upgrade-prompt.md)，让智能体只读检查目录、规则和痛点，给出路径对应表、拟议变更和冲突清单。
- **在备份副本中实践**：准备一份独立副本，明确授权智能体在副本内修改；先试一个真实的小任务，再对照检查。
- **应用到正式工作区**：依据副本实际差异和备份恢复方案，由使用者决定合并范围。原件、已有规则、日志、链接、已认可的历史成果应保留；迁移失败时可恢复。

这些步骤不是强制重建：现有结构已满足某项需要，就继续使用；先查已有规则与卡片，避免建立平行的第二份权威来源。改动具体文件时，保留其原有内容及权限边界，记录变更和回退路径。

## 逐项选择适用的改进

| 问题 | 可以添加的做法 |
|---|---|
| 每次都读全部知识 | 用一张短索引按任务类型路由；通用规则精简，历史材料只在相关风险出现时选读 |
| 项目续作接不上 | 为已有项目建立或补充当前状态、目标、交付、下步和证据入口 |
| 原件、结论和进度混在一起 | 在原有目录上明确各自权威位置，用链接关联，不必强行迁移 |
| 不知道哪些成果通过检查 | 在当前版本旁记录检查对象、方法、结果、未覆盖内容及用户确认状态 |
| 重复积累经验 | 优先更新已有知识条目；新结论保留来源、适用范围与状态，日志只记录变化 |
| 不同智能体不能自动找到规则 | 指向同一份规则源，提供工具支持的入口；无法自动加载时直接粘贴说明 |

## 验证与回退

至少检查：原资料和原有链接仍可访问；新增路径不与原规则冲突；模拟一次旧项目接续和一次经验选读；列出实际修改、未验证范围及恢复步骤。可使用自己的版本控制、文件备份或应用的恢复功能；不能将目录存在等同于恢复测试通过。

外部服务和文件访问由所选产品控制。没有文件访问能力的智能体只能基于你提供的片段提出建议，由你手动执行；涉及私密资料时，先确认该产品的数据处理方式与授权。
