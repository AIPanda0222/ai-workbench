# 与不同智能体配合

方法以普通 Markdown 和明确的步骤表达，任何能够理解文本的智能体都可以阅读其规则；能否直接完成建档、编辑和验收取决于产品功能、权限、运行环境和用户授权，无法保证所有智能体均已实测。

## 根据能力选择

1. **有本地目录读写能力**：打开目标目录并按提示授权。新建使用 [启动指令](agent-prompt.md)；已有框架使用 [改造提示词](upgrade-prompt.md)。确认智能体实际读取和修改的路径。
2. **只能读取上传的文件或应用资料库**：先提供允许分享的目录清单和少量规则，要求给出诊断与文件草稿；能否写回、是否需要人工导入由产品决定。上传前确认隐私和费用。
3. **只有聊天功能**：分批粘贴不含隐私的目录、规则及任务，要求输出可复制的修改建议、模板和操作步骤；由人保存文件、执行检查并反馈结果。它不能替代本地读取或写入。

如果工具有项目规则入口，可让它指向同一份规则源；否则每次把启动说明和相关内容贴入对话。具体产品示例及官方资料见 [兼容性](compatibility.md)。不要求使用 Obsidian 或特定插件。

建议先以虚构资料验证读取、任务选读、项目接续和权限边界，再用真实资料。无需为了证明兼容而上传隐私。
