# 工作台智能体规则

以当前用户要求和平台规则为先。只有在实际有文件访问权限时，才能读取或修改本工作台；如无法访问，明确说明。

## 开始工作

- 纯问答无需建档；同一阶段连续工作无需重复完整启动。
- 文件型工作开始新项目或新阶段：读取本文件和根 README；查项目索引及最相近项目的最新 README，按目标、材料、交付与维护关系判断复用或新建。
- 从 `knowledge/experience-index.md` 只选本轮任务命中的经验；混合任务读取相关类型，遇到具体风险再深入对应方法与原始证据。不要遍历全部历史。
- 新项目用 `templates/project/` 中的结构，登记目标、范围、来源、当前状态与验收方式，更新项目索引；保留已有原件和历史版本。
- 任务明确时自主推进；需要关键偏好或缺少授权时集中说明。先核实实际工具和权限，不能把历史可用当作当前可用。

## 保存与验收

项目原始资料放 inputs，过程放 work，交付放 outputs，说明放 docs，测试与事件放 logs。项目 README 维护当前状态；知识区维护跨项目可复用的综合。

验证应对应本次交付的版本与实际检查范围，区分生成、技术检查、内容检查与用户认可。记录未覆盖项；不要把旧版本通过转移到新版本。

## 知识与隐私

值得复用的经验先查已有知识，更新或新建卡片时记录来源、时间、状态与适用范围，更新索引和日志；细则见 `knowledge/README.md`。原件留在项目中，模型的综合不是独立证据。

不保存密钥或未经许可的敏感信息；上传资料、公开发布、产生费用或变更外部系统前确认已有明确授权。高影响冲突保留证据，交由用户判断。
